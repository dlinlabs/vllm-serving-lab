# Short envelope shadow measurements

This is a separate diagnostic collection path for the conditional envelope.
It does not run, relax or replace the failed point-readiness prerequisite in
entry-http. It never changes admission or authorizes model/HTTP/cap/MPC use.
The implementation is CPU/mock tested. The first reported native attempt exposed
a probe-transport defect; usable native interval measurements remain unverified.

## Frozen scope and denominator

The protocol is generated by `prefill_lab/envelope_shadow.py` and saved before
collection. Its source, plan, token manifest, support, runtime and clock domain
are bound in the configuration and seal before the first warmup:

- Four cases: empty engine; D16 decoding; mixed prefill plus a 50ms sentinel
  with D0; the same mixed case with D16.
- Four LIGHT warmups, retained separately without a prediction-readiness gate.
- Two repetitions of each case, each with OFF and LIGHT arms: 16 shadow trials.
  Arm order is OFF/LIGHT in repetition 1 and LIGHT/OFF in repetition 2.
- Total: 20 trials, 220 offered requests, 12 observed probes including warmups,
  and 8 OFF controls.
- Same exact content within each pair, disjoint from prior experiment content.
- Fixed protected32 gateway, B2048 engine, forced128 probe/foreground outputs
  and forced256 background outputs. No natural EOS, unknown arrivals or cap
  changes are modeled. Backgrounds must outlive foreground work.
- A 600-second limit from gateway startup through collection and shutdown,
  reserving 40 seconds for interrupted drain, final metrics and process cleanup.
  Engine/model startup, dependency installation, full native CPU validation and
  the final offline audit are outside it.

There is no automatic retry, sample deletion, support update or second
calibration attempt. A miss, wide interval or unavailable prediction does not
stop subsequent planned probes. A collection/integrity failure stops the run,
preserves the attempted prefix and remaining planned denominator, and archives
the attempt. Two repetitions are a diagnostic screen, not a coverage certificate.
After each trial, the collector verifies that a LIGHT sentinel actually entered
prediction and retained its start/finish/enqueue timestamps. An explicit
unavailable forecast is retained and collection continues. A silently skipped
prediction is an instrumentation failure: archive the raw trial and stop before
spending the remaining trials on an inactive predictor. This is not an accuracy
or point-readiness gate.

## Support must be explicit

`--support` accepts either:

1. An exact-runtime `state-time-support-v1` document. Runtime, implementation and
   dispatcher identities must still match. A restarted engine or another host
   does not silently inherit old empirical support.
2. An `envelope-shadow-assumptions-v1` input with explicit timing assumptions.
   It is bound to the newly observed runtime with `origin=explicit_assumptions`.
   This does not turn historical TRAIN bounds into fresh calibration.

The second format contains these fields:

```json
{
  "schema": "envelope-shadow-assumptions-v1",
  "gpu_lower_s": [0.008, 0.08, 0.0016, 0.0024, 0.0008, 0.0032],
  "gpu_upper_s": [0.012, 0.12, 0.0024, 0.0036, 0.0012, 0.0048],
  "prefill_return_s": [0.005, 0.06],
  "decode_return_s": [0.0005, 0.004],
  "policy": {"max_age_s": 0.005, "max_width_s": 0.01}
}
```

**These example numbers are illustrative, not recommended GPU parameters or
validated uncertainty bounds.** Choose and document the assumptions before
collecting new outcomes. Do not enlarge them after observing misses and call
that validation. The unmodified input is saved as `support-input.json`.

## Measurement, not admission

The native envelope configuration is independent of `live_configure`. It is
accepted only in explicit shadow mode on a drained, matching engine. Fixed
support/models are validated and copied once into `PreparedEnvelope`, before
the observation cut. A probe does not reread support files or rebuild models.
Changing the source/support/runtime requires a new configuration and run.
The HTTP probe marker is integer 0/1: the pinned vLLM OpenAI `vllm_xargs` schema
coerces JSON booleans to integers. Native selection accepts strict 0/1 and legacy
booleans, rejects malformed markers, and checks agreement with a supplied role.
OFF controls and non-sentinel requests still do not execute prediction.

The tracker reuses nonblocking pre-ADD snapshot hooks. It does not synchronize
CUDA, await a future or insert an admission decision. Each probe retains:

- snapshot start/cut, evaluation start, prediction finish and actual enqueue;
- request progress, pending work, scheduled timestamps and copy-ready bits;
- an ordered schedule/commit anchor log, including empty output batches, with
  each snapshot bound to the already-observed prefix of that log;
- the raw interval or the explicit unavailable/error outcome;
- completion age = prediction finish - snapshot cut;
- enqueue age = actual enqueue - snapshot cut;
- directly measured observer elapsed time, including snapshot work.

A narrow interval computed from a fresh input can still be too late when the
calculation finishes. Completion-age failure forces runtime fallback, and the
offline useful-prediction test additionally checks enqueue age and snapshot
width <=1ms. Fallback is a diagnostic result, not an actuator command.
`online_compute_age_qualified` remains false: measured budget checks do not
establish production timing guarantees.

## Independent analysis

The checker requires the current exact source, native CPU proof, installed vLLM
pins, sealed config/manifest/support, same-domain chronology and closed gateway
telemetry. It reconstructs results from raw snapshots, native requests/work,
client sidecars and the gateway journal, not saved scores.

Native active request identities, shapes, progress and pending work are checked
against the captured history. Pending scheduling times and the last commit are
rebuilt from the anchor log; native/probe timestamps must lie within the sealed
capture windows. Future commits cannot be input features or supply
missing ready bits. Unknown later arrivals and native work mismatches invalidate
usefulness/coverage. Copy-ready and the effective pending anchor are still
observations/model assumptions, not independently identified physical debt.
The native schedule hook starts after the trial's pre-schedule snapshot begins;
its timestamp need not equal the step start. The commit hook precedes the
trial's after-output timestamp. The audit preserves these inequalities rather
than treating nearby instrumentation clocks as identical.

For warmup and shadow groups separately, report planned/measured/unmeasured,
available/unavailable, covered/missed, wide, useful and fallback counts.
Timing summaries include sample counts, p50, p95 and maxima for interval width,
snapshot duration, completion/enqueue age and measured observer elapsed time.
Coverage conditional on availability has an explicit denominator; also report
covered/planned and useful/planned. Missing/interrupted/invalid evidence cannot
disappear by filtering to successful predictions.

OFF/LIGHT pairs report signed engine-latency differences and the pre-existing
max(2ms,10%) comparison budget. Balanced offered content/order does **not**
establish identical native states or causally isolate observer overhead.
Direct observer elapsed time and pair differences answer different questions.
Client TTFT joins remain in each row, but the interval target is engine time
from the pre-ADD cut, not an HTTP or pre-admission forecast.

`collection_complete` means a complete integrity-checked diagnostic collection.
It does not mean intervals passed, nor promote any acceptance flag.

## First reported native attempt: retain the failure

The user-provided output for `1793256266872988853` at commit `b7e007b` reported
20 completed trials but only 7 integrity-valid OFF controls, with no valid LIGHT
measurements. Eleven trials failed prediction chronology; two failed the
unchanged 5ms posting-lag limit. Inspected LIGHT sentinel records in `es-001` and
`es-006` had `status=off`, no prediction start/finish, and no forecast. The
boolean-to-integer wire conversion explains why the former `is True` check
silently skipped them. CPU regressions now exercise that conversion through the
HTTP producer and native ADD hooks; native CPU acceptance additionally exercises
the installed vLLM request schema when vLLM is installed.

The reported offending foreground posting lags in `es-011` and `es-019` were
approximately 5.19ms and 6.58ms. They remain scope failures, not accepted samples.
The corrected sender prepares fixed hashes and static JSON before offers and
foreground release, retaining a fresh actual send timestamp. This removes
avoidable timed work; it does not establish that native posting jitter now meets
5ms. No timing threshold or assumption box is widened.

These statements are based on supplied log/report/record excerpts, not a local
independent audit of the full archive. Preserve that archive and its original
source-bound report. Missing predictions cannot be recreated by relabeling OFF
records or recomputing with future information. A new source version needs fresh
CPU acceptance, configuration/seal and a separately archived collection.

## Commands

No GPU rental is needed for implementation or CPU tests. The following are
future native commands, not CPU-only validation commands:

```bash
python scripts/setup_prefill_calibration.py --next envelope-shadow --support /path/assumptions.json
.venv/bin/python scripts/prefill_host.py envelope-shadow --support /path/assumptions.json
```

Use a clean source checkout and the required Linux/Python3.12/vLLM environment.
The shadow operation does not require an unrelated Azure replay trace.

After collection and gateway shutdown, the independent checker can be rerun:

```bash
python scripts/check_prefill_envelope_shadow.py --capture /path/capture
```

It writes `shadow-report.json`, retains false acceptance flags and exits nonzero
for incomplete/invalid collection. Raw inputs are not modified. Early failures
before a seal or complete evidence exists remain archived failures, not
reconstructable interval measurements.
