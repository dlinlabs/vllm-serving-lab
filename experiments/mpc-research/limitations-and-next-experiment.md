# Limitations and next native experiment

## What this stage cannot establish

The CPU prototype is not a GPU/native/HTTP acceptance result. Historical
development traces support a useful factual backlog predictor, not causal
policy superiority. All successful captured outputs being128 tokens leaves
natural EOS/residual-life behavior unidentified. Synthetic scenario coefficients,
Poisson arrivals, independent mark resampling and initial-work beliefs are
assumptions, not newly measured dynamics.

Gateway reservation membership is not backend execution membership after a
cancellation. Prompt estimates are not exact KV allocations. Client scheduling,
gateway receipt, first SSE content, actual token emission and complete success
are distinct. Unknown GPU utilization, KV pressure and sensor delay stay unknown.
No chance-SLO, physical resource, recursive feasibility, stability or calibrated
counterfactual claim is made.

Finite-tail lower scoring can undervalue long successful streams; test tail
sensitivity and unresolved fractions. A small fixed action alphabet can miss a
better cap. A fixed synthetic model can misrank actions even with good factual
fit. Native optimal horizon, cadence, fallback and switching penalty remain open.
Deadline fallback is an observed operational result, not a threshold to relax.
Cooperative cancellation is not an OS hard-real-time guarantee.

The guarded API is a default-off primitive. Mock ASGI rejection tests cannot
qualify actual HTTP queueing, event-loop stalls, proxy buffering, write
acknowledgment loss, single-writer deployment or backend cancellation. The
released CLI remains shadow-only. Native enabling needs separately reviewed
artifact provenance, calibration, current-host state/action/fallback support
and deployment authorization.
The opt-in actuator library has durable pending-command and fencing tests;
its operator-attestation fields are not evidence that any native test ran.
The server retains at most1024 operation outcomes and refuses new operations
when full; it is not a long-running production retention design.

The literature review checked selected primary sources, not an exhaustive
2026 state-of-the-art or novelty search. Do not market the prototype as a
demonstrated state-of-the-art controller.

## Authorization-gated identification pilot

Do not start or extend a paid machine from this plan. A previous rental is not
assumed available or authorized. Proposed ceiling: one RTX4090 instance,
at most2.5 billable hours including setup; no additional paid services.
Cost ceiling must be explicitly approved as
`2.5 * provider_quoted_hourly_price + approved storage/network/minimum billing`.
No dollar amount is invented without the provider quote; the pilot does not
promise a completed final benchmark within that envelope.

Before spending, freeze source/model/tokenizer revisions, vLLM/CUDA/driver,
scheduler/configuration, cost/guard identities and separate train/calibration/
validation/test manifests. Restore the exact CPU-tested local branch rather
than silently taking a changed PR HEAD. Verify native schema and event clocks
first. If reusing the native envelope collector, rerun its old marker/role
chronology and5ms posting-scope qualification; do not relabel invalid captures
or widen that gate. The gateway-only MPC experiment does not require the
fixed-membership envelope oracle: qualify its own offered-load/HTTP timing
contract prospectively instead of copying an unrelated5ms gate.

Use at most48 development episodes averaging90s only if setup/drain/timing fit;
stop on the approved remaining wall/billing budget. First qualify fixed16/32,
coherent marked observation overhead, delayed/CAS/expired writes in the real
single-worker path, and complete client labeling. Randomize budget excitation
within supported bounds with drain/carryover accounting; vary offered rate,
prompt/output maximum, natural EOS, workload mix, saturation and recovery.
Keep intervention scope distinct from historical forced-token prefill probes.

Fit the smallest causal phase/residence model; evaluate one-step and multistep
errors, factual tail coverage, OOD behavior, request-state ablations and
counterfactual action contrasts under randomized support. Reject richer models
unless they improve untouched validation. Freeze selected policies before test.

The pilot determines episode variance, actual duration, action support, observation
delay and solver cost. Then propose a separate confirmatory benchmark budget:
same hardware/model/runtime, identical offered traces/warmup/seeds, tuned fixed
and same-state feedback plus one-move and MPC, randomized episode order,
complete outcomes and block-level uncertainty/multiplicity. If evidence cannot
resolve a win, report uncertainty or a rigorous negative result. Do not infer
equivalence merely because a confidence interval contains zero.
